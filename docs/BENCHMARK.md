# 基准测试方法与原始数据

所有数字均为本机实测（2026-11-03 晚 ~ 11-04 凌晨），非估算。

## 环境

| 项 | 值 |
|---|---|
| 系统 | fnOS 1.2.0800（trim） |
| 官方影视 | trim.media 0.9.8-1 |
| 被测扩展 | 原版 v0.2.39 ↔ Turbo v1.0.0（同一台机，同一源站） |
| 出网基线 | 单连接 1.05 MB/s（8.4 Mbps）；6 连接并行合计 ≈ 9.2 MB/s（74 Mbps） |
| 局域网 | 千兆；测量点为本机 unix socket，排除局域网因素 |
| 片库规模 | 3071 部在线片，state/titles.json 65 MB |

## 测量方法

1. **起播耗时**：用 TV 端 UA（`1.4.2 (com.trim.tv; ...) okHttp/4.9.0`）向
   `/v/media/online/<mg>/main.m3u8?index=0&auto=1` 发请求，`curl -w %{time_total}` 计时。
   这是播放器在拿到主清单前必须等待的时间（含竞速 + 播放列表构建 + 首分片验活）。
2. **分片首字节**：请求清单里改写后的 `seg?u=<b64>` 地址，记录 `%{time_starttransfer}`
   与 `%{time_total}`；原版两者相等（整段缓冲后回传），Turbo 两者分离（流式）。
3. **线路吞吐**：用 httpx 对同一部片的首分片发 `Range: bytes=0-400000` 请求，
   用 `len(body)/耗时` 计算；也交叉验证过播放时日志里的吞吐记录。
4. **DNS**：`socket.getaddrinfo(host, 443)` 计时，覆盖 18 个源域名（首次/二次各一次）。

## 复现

```bash
# 起播耗时
MG=<media_guid>
curl -s -o /dev/null -w 'startup=%{time_total}s\n' \
  -H 'User-Agent: 1.4.2 (com.trim.tv; build:14209; Android 35) okHttp/4.9.0' \
  --unix-socket /var/run/trim_media.sock \
  "http://x/v/media/online/$MG/main.m3u8?index=0&auto=1"

# 选线情况（Turbo 会打印实测吞吐）
journalctl -u fnmedia-ext.service -f | grep 竞速
```
